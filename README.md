## 🧠 核心方法论

```
消费端需求（平台A × 平台B）  →  我方供给（内部投放）  →  历史季节验证
        ↓                           ↓                      ↓
  四类需求来源标签             重/中/轻供给+动量         去年排名+商品基础
        ↓                           ↓                      ↓
        └───────────────────────────┼──────────────────────┘
                                    ↓
              四类最终结论：市场缺口 / 已布局 / 市场饱和 / 观察验证
```

### 关键设计（与拍脑袋的做法有什么不同）

| ❌ 旧做法 | ✅ 本方法论 |
|---|---|
| 固定 10% 判「热门/缺口」 | 平台内 30%—40%—30% 相对排名 |
| 固定 12%/6% 区分重投/轻投 | 近 4 周内部 GMV 排名分层 |
| 「抖音强 = 视频号红海」 | 「抖音强 = 待迁移验证的外部机会」 |
| 单凭投放规模高 = 饱和 | 需求 + 供给 + 效率三类证据齐全才判 |
| 只看视频号 / 只看抖音 / 只看我方投放 | 三层证据交叉验证 |

### 四类结论

| 结论 | 条件 | 动作 |
|---|---|---|
| 🟢 **市场缺口** | 需求已验证 + 我方轻供给或收缩 + 效率不差 | 迅速拓品切入 |
| 🔵 **已布局** | 需求已验证 + 我方已有中高供给 | 按动量调整运营 |
| 🟡 **观察验证** | 需求/历史/效率证据不足 | 小规模引入补证据 |
| ⚪ **市场饱和** | 需求收缩 + 供给过载 + ROI 走弱（缺一不可） | 管控预期，输入替代品 |

## 🚀 快速开始

### 场景一：做美护行业选品拓品

在新会话中粘贴 `新会话启动Prompt_美护选品拓品最终分析.md` 全部内容。Agent 会自动读取项目记忆和分析框架，产出最终榜单。

### 场景二：接入新行业（食饮 / 3C / 家居 / 服饰等）

1. 在 IDE 聊天框说「帮我做 XX 行业的选品拓品分析」
2. Agent 会自动读取 `SKILL_xuanpin_tuopin_cross_industry.md` 中的方法论
3. 先完成「行业建模」四步（确认范围 → 建赛道桶 → 归桶映射 → 匹配率验收）
4. 再进入标准三层分析链 → 产出最终榜单

详细接入步骤见 `SKILL_xuanpin_tuopin_cross_industry.md` §七。

## 🔒 数据脱敏

对外版 HTML 报告对以下数据做了脱敏处理：

| 数据类型 | 脱敏方式 |
|---|---|
| 第三方平台 GMV / 消耗 | 需求指数（各平台最高赛道=100）+ 排名 |
| 内部 ROI | 区间化（高/中/一般） |
| 精确 SPU / 客户数 | 区间化（宽/中/窄） |
| 客户/品牌/店铺名 | 隐去 |
| 历史商品明细 | 泛化为代表商品型 |
